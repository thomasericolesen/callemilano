# CalleMilano remediation plan

This plan converts every issue listed in `docs/architecture-review.md` into a prioritized action. It recommends a single canonical solution for each issue. It does not make those changes.

## Priority levels

- **P0 — Contract blockers:** resolve before importing more records or automating agents.
- **P1 — Operational foundation:** resolve before scaling the catalog or relying on agent output.
- **P2 — Product and discovery:** resolve before public launch or significant SEO growth.
- **P3 — Ongoing governance:** establish before the content library grows substantially.

## P0 — Contract blockers

| Issue and problem | Affected files | Single canonical solution |
|---|---|---|
| **Conflicting storage conventions:** `AGENTS.md` directs structured records to `data/`, while both agent specs use `docs/places/`. | `AGENTS.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md`; examples | Declare `docs/places/` the sole canonical location for place records and update all project instructions to match. |
| **Category vocabulary mismatch:** Guidance says `Cities`, while schema uses `City`, so records may fail validation or split filters. | `AGENTS.md`; `docs/place-schema.md`; examples; agent specs | Adopt the schema's singular `City` enum as canonical and update every occurrence and example. |
| **Contradictory audience definitions:** Guidance uses informal groups such as toddlers and teens, while schema requires fixed age bands plus suitability scores. | `AGENTS.md`; `docs/place-schema.md`; examples; agent specs | Make the schema's five age-band labels and `family_score` keys the sole controlled representation across the project. |
| **Lifecycle/status is required but undefined:** Agent documents require draft status and status transitions, but the record schema has no status field. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md`; examples | Add one required `status` enum to the schema and specify allowed transitions from draft through approval, publication, and archive. |
| **Unresolved values conflict with “complete” records:** Examples use nulls and phrases such as “Not yet verified,” but the schema does not say where those values are valid or what blocks a handoff. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md`; examples | Define an explicit per-field unknown representation and validation rules by status, allowing unresolved data in drafts and rejecting it where publication requires verified values. |

## P1 — Operational foundation

| Issue and problem | Affected files | Single canonical solution |
|---|---|---|
| **Provenance and audit trail are incomplete:** One last-verified date cannot show who checked each claim, what source supports it, or how a record changed. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Add a structured claim/source evidence ledger with source URL, claim/field supported, checked date, agent or editor, and change history for each record. |
| **Administrative geography is incomplete:** Region and country are absent although the scope covers Spain and IDs encode region. | `docs/place-schema.md`; examples; `docs/maps-import-agent-spec.md` | Add canonical `autonomous_community` and `country` fields, with consistent Spanish administrative names and codes. |
| **Useful official and visitor links are not modeled:** Records have a Maps URL but no dedicated official website, booking, contact, or visitor information fields. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; examples | Add an optional typed `links` object for official site, booking, visitor information, transport, and contact destinations. |
| **Opening and visit-planning facts are underspecified:** Season labels cannot represent schedules, visit duration, reservation lead time, or validity dates. | `docs/place-schema.md`; `AGENTS.md`; agent specs | Add optional, source-dated visit-planning fields for schedule, typical duration, booking lead time, and seasonal validity. |
| **Accessibility fields overlap and lack scope:** `accessibility` and `wheelchair_friendly` can conflict and omit sensory, mobility-route, and accessible-facility detail. | `docs/place-schema.md`; examples; agent specs | Define one structured accessibility object with separate mobility, sensory, route, and facility attributes; derive any simple summary label from those attributes. |
| **Parking and other transport detail is too generic:** Current parking summary cannot distinguish onsite from nearby parking, cost, restrictions, distance, or non-car access. | `docs/place-schema.md`; examples; agent specs | Define structured transport options, with parking as a typed option including location, type, cost, restrictions, and walk distance. |
| **Cost level is subjective and incomparable:** Euro symbols lack a defined party size, basis, date, or included costs. | `docs/place-schema.md`; examples; agent specs | Define euro-symbol tiers as qualitative per-person core-experience estimates and require a checked date plus a short basis; keep incidental costs separate. |
| **Image role and provenance lifecycle are incomplete:** The image object lacks role and asset identity, while rights may change separately from place facts. | `docs/place-schema.md`; `AGENTS.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Give each image a stable asset ID and role, with independently maintained source, rights, credit, and rights-review status. |
| **External identity and coordinate intent are weakly represented:** A Maps URL alone may change or be ambiguous; town coordinates need a representative-point convention. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; examples | Add optional external IDs and a required coordinate purpose (`venue`, `entrance`, `town_center`, etc.) with a documented representative-point rule. |
| **Canonical page slug is unspecified:** Stable IDs do not establish the public URL or define how a rename affects it. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Add a unique `slug` field and define that URL changes require an explicit redirect record. |
| **Related-place relationships are absent:** Nearby recommendations and itinerary relations would otherwise be duplicated or maintained as unstructured prose. | `docs/place-schema.md`; `docs/multi-agent-workflow.md` | Add optional relationship fields that reference other stable place IDs with a controlled relationship type. |
| **Creation, update, and review dates are missing:** `last_verified` alone does not show record age, editorial updates, or review deadlines. | `docs/place-schema.md`; agent specs; examples | Add `created_at`, `updated_at`, `last_reviewed_at`, and `next_review_at` with defined update semantics. |
| **Bulk intake and queue management are undefined:** Single-place intake gives no duplicate scan, batch progress, retry, or unresolved-item queue. | `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Define a batch intake queue with per-place identity, status, retry count, and duplicate resolution before agent processing. |
| **Clarification handling has no resume contract:** Ambiguous records can pause for user input without preserving the question or resuming state. | `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Record the ambiguity and pending question in the intake item, then resume the same item after the user's answer. |
| **Field verification has no claim-to-source structure:** Bottom-of-file source notes may not show which source supports each fact. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Require a claim-level evidence ledger linking each material field or claim to one or more sources and checked dates. |
| **Review and approval are underspecified:** Human review lacks a designated role, sign-off record, criteria, and rework loop. | `docs/multi-agent-workflow.md`; `docs/maps-import-agent-spec.md`; `docs/place-schema.md` | Define an editor-of-record approval step that records reviewer, decision, date, and requested changes in the place lifecycle. |
| **Update, archive, and correction processes are absent:** Closure, stale content, reopenings, and public corrections have no defined maintenance path. | `AGENTS.md`; `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Define a maintenance lifecycle for corrections, closures, reopening, stale-data review, and archival, owned by the editorial reviewer. |
| **Regression validation is not part of the workflow:** No gate checks schema keys, YAML, enums, duplicate IDs, links, or duplicate SEO. | `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md`; `docs/place-schema.md` | Make automated record validation a mandatory final workflow gate before human approval. |
| **Image rights review has no operational process:** The rules prohibit assumptions but do not define asset intake, permission evidence, credit maintenance, or withdrawal. | `AGENTS.md`; `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; workflow | Use a centralized image-rights ledger keyed by asset ID, and allow publication only while its permission state is valid. |
| **Agent disagreement has no final authority:** Disputed source or classification can loop without a decision owner or confidence threshold. | `docs/multi-agent-workflow.md`; `docs/maps-import-agent-spec.md`; `AGENTS.md` | Assign the human editor-of-record final authority over unresolved factual conflicts and editorial classification decisions. |
| **Failure reporting is inconsistent:** Errors have no shared severity, result codes, retry rules, or escalation path. | `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Define one shared issue report format with severity, affected fields, retryability, owner, and escalation state. |
| **Schema versioning and migration are absent:** The workflow refers to a schema version that does not exist. | `docs/place-schema.md`; `docs/multi-agent-workflow.md`; examples | Add a schema version identifier and a migration policy; every record declares the version it follows. |
| **ID allocation can collide:** The ID template has no registry, number assignment, or concurrent allocation rule. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Allocate IDs from a single registry using a deterministic namespace and collision-checked sequence. |
| **Source-of-truth format is undecided:** Markdown with embedded YAML can be parsed, but it is unclear whether it is canonical or generated from another dataset. | `AGENTS.md`; `docs/place-schema.md`; agent specs; examples | Declare Markdown files with YAML front matter as the canonical record source and prohibit a second editable copy of place data. |
| **No catalog/index exists:** There is no canonical mechanism to discover records, detect duplicates, or feed site generation. | `AGENTS.md`; `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; workflow | Maintain a generated catalog index from canonical place files, keyed by stable ID and including status, category, and slug. |
| **Shared-file edits can overwrite one another:** Agents edit the same file without ownership or conflict detection. | `docs/multi-agent-workflow.md`; `docs/maps-import-agent-spec.md` | Assign one active agent as file owner per handoff and require version-checked patch application before saving. |
| **Taxonomy has no change control:** There is no owner or process for adding, merging, aliasing, or retiring tags. | `AGENTS.md`; `docs/place-schema.md`; agent specs; workflow | Make the human editor-of-record the taxonomy owner and require a documented schema change proposal for vocabulary edits. |

## P2 — Product and discovery

| Issue and problem | Affected files | Single canonical solution |
|---|---|---|
| **SEO technical contract is incomplete:** Title and description do not govern canonical URL, indexability, social metadata, structured data, or redirects. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Add one SEO page contract covering slug, canonical URL, robots/indexability, social metadata, structured data, and redirects. |
| **No duplicate-target policy:** Unique metadata is requested without site-wide checks for duplicate places or overlapping destination pages. | `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md`; SEO contract to be added | Require a catalog-wide duplicate and page-intent check before a page is approved. |
| **Localization policy is absent:** Spanish spelling is preserved, but publication language, translated fields, slugs, and `hreflang` are undecided. | `AGENTS.md`; `docs/place-schema.md`; agent specs; workflow | Define English as the source editorial locale and require locale-keyed translations with locale-specific slug and `hreflang` metadata for additional languages. |
| **SEO guidance is not measurable:** There are no target ranges or preview guidance for title and description. | `AGENTS.md`; `docs/place-schema.md`; SEO Agent workflow | Set recommended title and description character ranges and require a SERP preview check while allowing search truncation. |
| **Page intent and scope are undefined:** A town page may compete with separate attraction, beach, or venue pages. | `docs/place-schema.md`; `docs/multi-agent-workflow.md`; SEO contract to be added | Assign each record a page type (`destination` or `specific_place`) and define parent/child canonical relationships for overlapping coverage. |
| **Image SEO and delivery rules are absent:** Alt text is defined, but filenames, responsive dimensions, captions, and performance are not. | `docs/place-schema.md`; `AGENTS.md`; image workflow | Establish one image publishing standard for descriptive asset naming, responsive variants, captions, compression, and accessible alt text. |
| **Internal linking model is absent:** Nearby places and related categories are not connected for users or site structure. | `docs/place-schema.md`; workflow; SEO contract to be added | Use stable-ID references for nearby/related places and require relevant internal links on destination and place pages. |
| **Structured-data governance is missing:** No rules determine schema.org types or ensure markup matches page content. | `docs/place-schema.md`; SEO Agent workflow | Define a single mapping from approved page types to schema.org types and emit markup only from verified visible fields. |

## P3 — Content governance and ongoing operations

| Issue and problem | Affected files | Single canonical solution |
|---|---|---|
| **Ownership is undefined:** Taxonomy, final approval, disputes, schema changes, and urgent corrections have no named accountable role. | `AGENTS.md`; `docs/multi-agent-workflow.md`; `docs/maps-import-agent-spec.md` | Assign one human editor-of-record accountable for taxonomy, schema, approval, disputes, and correction escalation. |
| **Examples can look publishable despite unverified values:** Example records contain ratings, prices, and facilities without uniform draft labeling. | `docs/place-schema.md`; `docs/examples/*.md`; `docs/maps-import-agent-spec.md` | Mark every example `status: example` or an equivalent non-publishable schema state and require explicit evidence for non-unknown claims. |
| **Evidence standards are vague:** “Official and authoritative” lacks a minimum quality, confidence, and exception policy. | `AGENTS.md`; `docs/maps-import-agent-spec.md`; `docs/multi-agent-workflow.md` | Adopt a source-quality rubric that specifies acceptable authority levels and requires an explicit exception note for secondary sources. |
| **Data rights and retention policy is incomplete:** Google Maps, source links, personal information, and image permissions have no comprehensive project policy. | `AGENTS.md`; `docs/place-schema.md`; import spec; workflow | Publish a source and rights policy defining permitted facts/metadata, attribution, retention, privacy handling, and image licensing. |
| **Review cadence is absent:** No field-specific schedule identifies stale hours, prices, access, or seasonal information. | `docs/place-schema.md`; `docs/maps-import-agent-spec.md`; workflow | Define review intervals by volatility class and drive a due-review queue from each field's verification date. |
| **Accessibility and family ratings lack a review standard:** These claims can affect safety and usability, but no evidence threshold or reviewer qualification exists. | `AGENTS.md`; `docs/place-schema.md`; examples; workflow | Require source-backed criteria and human review for accessibility and family-suitability claims, with unknown used where evidence is insufficient. |
| **No reader correction channel exists:** There is no intake route or response owner for reports from visitors or venues. | `AGENTS.md`; `docs/multi-agent-workflow.md`; future website documentation | Establish one correction-report channel linked from place pages and route submissions to the editor-of-record with a defined response target. |
| **Voice and language conventions are incomplete:** Tone, date/units style, translations, and local naming variants are not fully standardized. | `AGENTS.md`; `docs/place-schema.md`; editorial workflow | Create one editorial style guide defining source locale, voice, units, dates, place-name treatment, and translation review. |

## Execution order

1. Complete the P0 contract decisions and update all instructions and examples together.
2. Establish the P1 schema, provenance, lifecycle, ownership, validation, ID, and storage foundations.
3. Add the P2 SEO, localization, page-scope, and linking contract before public page generation.
4. Put P3 governance and maintenance rules in place before the catalog becomes large or public corrections accumulate.

## Completion criterion

Remediation is complete when every P0–P3 item has one approved canonical rule, all source documents and examples agree with it, existing records are migrated, and the validation/review workflow can identify violations before a record advances to approval.
